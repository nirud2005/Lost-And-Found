# 🎒 Smart Lost & Found – ของหายได้คืน มศว

เว็บแอประบบประกาศของหาย/ของที่เก็บได้ สำหรับนิสิตมหาวิทยาลัยศรีนครินทรวิโรฒ (ประสานมิตร)
เป็นไฟล์ `index.html` ไฟล์เดียว ไม่ต้องติดตั้งหรือ build เปิดในเบราว์เซอร์ก็ใช้งานได้ และเผยแพร่เป็นลิงก์ด้วย GitHub Pages ได้ฟรี

> ต้องมีอินเทอร์เน็ตตอนใช้งาน เพราะโหลดฟอนต์ ไอคอน Tailwind และโมเดลสแกนจาก CDN

## ฟังก์ชันหลัก

|---|---|

| หน้าหลัก | แถบค้นหาพร้อมปุ่มสแกนด่วน, แบนเนอร์ประชาสัมพันธ์เร่งด่วน, หมวดหมู่ (กระเป๋า, มือถือ, กุญแจ, บัตรนิสิต, เอกสาร, เสื้อผ้า, อุปกรณ์การเรียน, อื่นๆ) และรายการล่าสุด |

| ยืนยันตัวตน | ตรวจผ่านบัตรนิสิต มศว, บัตรประชาชน และ OTP พร้อมพรางข้อมูลบางส่วน |
| แจ้งเตือน | แยกแท็บ ทั้งหมด / ของหาย / ของที่เก็บได้ / ระบบ |

| **แอดมิน (เดโม่)** | ศูนย์จัดการของหายสำหรับเจ้าหน้าที่แต่ละจุดรับฝาก ดูหัวข้อ "หน้าแอดมิน (เดโม่)" ด้านล่าง |

## เรื่องรูปภาพและการสแกน

- รูปตัวอย่างทั้ง 5 รายการเป็นภาพประกอบ (SVG) ที่ตรงกับชื่อสิ่งของ ไม่ได้ใช้รูปสต็อกที่อาจไม่ตรงคำอธิบาย
- ฟอร์มสร้างประกาศเริ่มต้น **ไม่มีรูป** ถ้าไม่แนบ ระบบใส่ภาพ "ยังไม่มีรูป" แทน (ไม่ใช่รูปกระเป๋าอีกต่อไป)
- สแกนรูปรู้จักสิ่งของทั่วไป เช่น กระเป๋า มือถือ แว่น รองเท้า เสื้อ ขวดน้ำ ร่ม แต่ **ไม่รู้จัก "บัตร" และ "กุญแจ" โดยตรง** ผลจึงเป็นตัวช่วยเติมฟอร์ม ควรตรวจแก้ก่อนโพสต์ ถ้าจำแนกไม่ได้ระบบจะบอกตรง ๆ และใส่หมวด "อื่น ๆ" พร้อมสีเด่น
- ถ้าโหลดโมเดลไม่ได้ (ออฟไลน์) จะอ่านได้เฉพาะสี
- กล้องต้องเปิดผ่าน https (GitHub Pages ใช้ได้) และผู้ใช้ต้องกดอนุญาต ถ้าไม่อนุญาตจะใช้แกลเลอรี่แทน

## บทบาทผู้ใช้ (ผู้ตามหา / ผู้พบ / แอดมิน)

แชท ปุ่มคำตอบด่วน ปฏิทิน และป้าย "ตอนนี้คุณใช้งานในฐานะ" ปรับตามบทบาทเมื่อเทียบกับประกาศ

| สถานการณ์ | บทบาท | คู่สนทนา |
|---|---|---|
| เจ้าของประกาศ "ของหาย" | ผู้ตามหา | ผู้พบ |
| เจ้าของประกาศ "ของที่เก็บได้" | ผู้พบ | ผู้มาขอรับ |
| คนอื่นเปิดประกาศ "ของหาย" | ผู้พบ | เจ้าของ |
| คนอื่นเปิดประกาศ "ของที่เก็บได้" | ผู้ตามหา | ผู้พบ |
| เจ้าหน้าที่ | แอดมิน | ผู้ใช้งาน |

บทสนทนาเริ่มต้นเป็นข้อความตัวอย่าง ข้อความที่ผู้ใช้พิมพ์เองจะต่อท้ายและไม่ปนกันระหว่างบทบาท
ปฏิทินแสดงจุดสีจากประกาศจริงเท่านั้น

## อะไรใช้งานจริง อะไรยังเป็นเดโม่

ควรอ่านก่อนเปิดให้คนอื่นใช้ เพื่อไม่ให้ผู้ใช้เข้าใจผิด

| ส่วน | ไม่ตั้งค่า Supabase | ตั้งค่า Supabase แล้ว |
|---|---|---|
| ประกาศ (โพสต์ / ดูรายการ / เปลี่ยนสถานะเป็นรับคืนแล้ว) | เห็นเฉพาะในเครื่องตัวเอง | **ทุกคนเห็นร่วมกัน** |
| รูปที่แนบในประกาศ | อยู่ในหน้าเว็บ | **เก็บบน Supabase Storage** (ย่อเหลือด้านยาวไม่เกิน 1024px) |
| เข้าสู่ระบบ, SSO, ยืนยันตัวตน | จำลอง | จำลอง (ยังไม่มีระบบบัญชีจริง) |
| แชทระหว่างผู้ใช้ | จำลอง เก็บในหน้าเว็บ | จำลอง ยังไม่ส่งถึงอีกเครื่อง |
| สแกนรูป | วิเคราะห์ในเครื่องจริง (ต้องต่ออินเทอร์เน็ตตอนโหลดโมเดลครั้งแรก ~15 MB) | เหมือนกัน |
| AI น้องนำทาง | คำตอบตัวอย่างตายตัว | คำตอบตัวอย่างตายตัว |
| แจ้งเตือน | สร้างในหน้าเว็บของตัวเอง | สร้างในหน้าเว็บของตัวเอง |
| ปฏิทินกิจกรรม | ข้อมูลตัวอย่าง (ตุลาคม 2568) | ข้อมูลตัวอย่าง |
| **หน้าแอดมิน** | ข้อมูลตัวอย่างในเครื่อง | ข้อมูลตัวอย่างในเครื่อง **ไม่เชื่อมฐานข้อมูลจริง** |

แอปมีรายการตัวอย่าง 5 รายการติดมาด้วยเสมอ เพื่อให้หน้าจอไม่ว่างและปฏิทินอ้างอิงได้

## หน้าแอดมิน (เดโม่)

ศูนย์จัดการของหายสำหรับเจ้าหน้าที่ ทำขึ้นเพื่อ**เสนอและทดสอบขั้นตอนงาน** ใช้ข้อมูลตัวอย่างที่เก็บในเบราว์เซอร์ของเครื่องนั้น (`localStorage`) **ไม่ส่งข้อมูลออกนอกเครื่องและไม่แตะฐานข้อมูล Supabase** หน้าจอมีป้าย `DEMO` และแถบแจ้งโหมดเดโม่ตลอดเวลา

**วิธีเข้า:** หน้าโปรไฟล์ → กล่อง "สลับบัญชีเพื่อทดสอบระบบ" → **แอดมิน มศว** (บนจอคอมพิวเตอร์กดรายการที่ 14 "แอดมิน (เดโม่)" ในแผงด้านขวาได้เลย) กดปุ่ม "ออก" มุมขวาบนเพื่อกลับเป็นนิสิต

**แยกตามจุดรับฝาก:** มี 3 จุดตัวอย่าง คือ หอสมุดกลาง (อาคาร 25), สำนักงานอธิการบดี (อาคาร 9) และอาคารเรียนรวม (อาคาร 31) เจ้าหน้าที่แต่ละจุดเห็นและจัดการได้เฉพาะของที่ฝากไว้ที่จุดตัวเอง (กดชื่อจุดที่หัวหน้าจอเพื่อสลับจุดทดสอบ)

| เมนู | ทำอะไรได้ |
|---|---|
| ภาพรวม | ตัวเลขของที่ถืออยู่ / คำขอรอตรวจ / ค้างเกิน 30 วัน / ส่งคืนแล้ว, รายการ "ต้องทำตอนนี้", อัตราส่งคืนและเวลาเฉลี่ย, กราฟของที่รับเข้า 7 วัน |
| คำขอรับคืน | ตรวจคำขอโดยเทียบ "ที่ผู้ขอแจ้ง" กับ "ที่บันทึกไว้ภายใน" แล้ว **อนุมัติ** (ต้องติ๊กยืนยันว่าตรวจบัตรตัวจริงและลักษณะตรงกัน) / **ขอข้อมูลเพิ่ม** / **ปฏิเสธ** พร้อมเหตุผล |
| ของที่ถือ | ค้นหา/กรอง, ดูข้อมูลภายใน, **ส่งมอบตรง** ที่จุดรับฝาก, **ย้ายเป็นของค้าง** เมื่อครบ 30 วัน, **รับของเข้า** ใหม่ |
| บันทึก | ประวัติการดำเนินงานของจุดนั้น |

ข้อมูลตัวอย่างเก็บใน `localStorage` คีย์ `swu_admin_demo_v1` รีเซ็ตกลับค่าเริ่มต้นได้ที่หน้าเลือกจุดรับฝาก

> **คำเตือน:** แอปยังไม่มีระบบบัญชีจริง ใครก็กดสลับเป็นแอดมินในหน้าโปรไฟล์ได้ หน้านี้จึง**ห้ามใช้กับข้อมูลหรือสิทธิ์จริง** การทำเป็นแอดมินจริงต้องมี Supabase Auth จำกัดอีเมล `@g.swu.ac.th` กำหนดสิทธิ์แอดมินและจุดรับฝากรายบุคคล และบังคับสิทธิ์ที่ฐานข้อมูล (RLS) ไม่ใช่แค่ซ่อนปุ่มในหน้าจอ

### เมนูแผงด้านขวาในโหมดแอดมิน
เมื่อสลับเป็นแอดมิน เมนูด้านขวาเปลี่ยนเป็นของแอดมิน (ภาพรวม, คำขอรับคืน, ของที่ถือ, บันทึก, รับของเข้า, เปลี่ยนจุด, รีเซ็ต, ออก) และกดแล้วหน้าซ้ายเปลี่ยนตาม
แอดมินสามารถ **โอนย้ายของไปจุดรับฝากอื่น** ได้ (คำขอรับคืนย้ายตามไปด้วย และมีบันทึกทั้งสองฝั่ง)

## เผยแพร่ด้วย GitHub Pages

1. สร้าง repository ใหม่บน GitHub (Public) เช่น `swu-lost-found`
2. อัปโหลดไฟล์ `index.html`, `README.md`, `LICENSE.txt`, `supabase-setup.sql`
3. ไปที่ **Settings → Pages** ตรง **Source** เลือก **Deploy from a branch** เลือก branch `main` โฟลเดอร์ `/ (root)` แล้วกด **Save**
4. รอ 1–2 นาที เว็บจะอยู่ที่ `https://<your-username>.github.io/swu-lost-found/`

## เปิดระบบฐานข้อมูล (ให้ทุกคนเห็นประกาศร่วมกัน)

ใช้ [Supabase](https://supabase.com) แพ็กเกจฟรี

1. สร้างโปรเจกต์ใหม่ที่ supabase.com
2. ไปที่ **SQL Editor** วางเนื้อหาไฟล์ `supabase-setup.sql` แล้วกด **Run** (สร้างตารางประกาศ นโยบายความปลอดภัย และที่เก็บรูป)
3. ไปที่ **Project Settings → API** คัดลอก **Project URL** และ **anon public key**
4. เปิด `index.html` ค้นหาบรรทัด `const SB_URL='',SB_KEY='';` (อยู่ท้ายไฟล์) แล้วใส่ค่าสองตัวนั้น เช่น
   `const SB_URL='https://xxxx.supabase.co',SB_KEY='eyJ...';`
5. อัปโหลด `index.html` ขึ้น GitHub ทับของเดิม แล้วรอ GitHub Pages อัปเดต

ถ้าเชื่อมต่อสำเร็จ ใน Console ของเบราว์เซอร์ (F12) จะขึ้นข้อความ `เชื่อมต่อ Supabase แล้ว` และถ้า Supabase ใช้ไม่ได้ชั่วคราว แอปจะกลับไปใช้โหมดเดโม่เอง

### ข้อควรรู้เรื่องความปลอดภัย

- anon key เปิดเผยในโค้ดได้ตามการออกแบบของ Supabase ความปลอดภัยอยู่ที่นโยบาย RLS ใน `supabase-setup.sql` **ห้ามใส่ service_role key ในไฟล์นี้เด็ดขาด**
- ตอนนี้แอปยังไม่มีระบบบัญชีจริง ดังนั้น **ใครก็โพสต์ประกาศและกดเปลี่ยนสถานะ (เช่น "รับคืนแล้ว") ได้** แต่แก้ข้อความ รูป หรือลบประกาศไม่ได้
- ช่องทางติดต่อที่ผู้ประกาศกรอกจะเก็บอยู่ในประกาศ ซึ่งทุกคนอ่านได้ ตัวเลือกซ่อนเบอร์ในแอปเป็นการซ่อนที่หน้าจอเท่านั้น ไม่ได้ซ่อนในฐานข้อมูล จึงไม่ควรให้ผู้ใช้กรอกข้อมูลที่อ่อนไหว
